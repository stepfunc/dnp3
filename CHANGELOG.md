
### 1.8.0-M2 ###
* :shield: Time out a TLS outstation server's handshake after 5 seconds. The server accepts one connection at a time, so a peer that passed the address filter and then stalled its TLS handshake stopped the server from accepting connections for any of its outstations until the peer disconnected. Sessions already running were unaffected, and plain TCP servers weren't affected. Every release with TLS support is affected. A peer that keeps opening stalled connections can still delay new connections by up to 5 seconds each. See [#532](https://github.com/stepfunc/dnp3/pull/532).
* :shield: Time out a TLS client's handshake after 5 seconds, for masters and outstations that connect with TLS. A server that accepted the connection and then stalled the handshake stopped the client from retrying or moving on to its other endpoints until the server disconnected. See [#533](https://github.com/stepfunc/dnp3/pull/533).
* :shield: Keep TCP servers accepting connections after an accept error. The first error, such as running out of file descriptors, stopped an outstation server for good, with every outstation on it shut down, or ended a master server, without telling the user. Connection-level errors are now retried at once and other errors after 1 second. Every release is affected; we found no way for a remote peer alone to cause the stop, so the realistic trigger is descriptor exhaustion in the process. See [#638](https://github.com/stepfunc/dnp3/pull/638).
* :shield: Update `rustls-webpki` to 0.103.16 to resolve [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382), in which certificate paths through distrusted emSign intermediates could be accepted. dnp3 trusts only the CA file it is configured with, so this requires `CertificateMode::AuthorityBased` with a public emSign root in that file; `CertificateMode::SelfSigned` is not affected. The update only matters for the prebuilt binary distributions of the bindings (C/C++, .NET, Java). See [#505](https://github.com/stepfunc/dnp3/pull/505).
* :bell: `RetryStrategy` now raises a minimum or maximum delay of zero to 1 ms and swaps a reversed minimum and maximum, including when deserialized. A minimum of zero never backed off, so a refused connection retried in a tight loop. See [#570](https://github.com/stepfunc/dnp3/pull/570).
* :shield: File AUTHENTICATE passwords and auth keys are no longer printed by object value decode logging or by the `Debug` output of `FileCredentials` and `AuthKey`. See [#520](https://github.com/stepfunc/dnp3/pull/520).
* :shield: Discard empty UDP datagrams instead of ending the session. A zero-length datagram was treated as the end of the stream, so any host that could reach a bound UDP master or outstation could end its session, and keep it down by repeating it after each reopen. Connected UDP sockets only accept datagrams from their peer. TCP, TLS and serial are not affected. See [#544](https://github.com/stepfunc/dnp3/pull/544).
* :shield: Keep a bound UDP master or outstation running when it can't reply to a datagram's source. A datagram from port 0, or from any address the socket couldn't send to, made the reply fail and ended the session, closing the socket until it reopened, the same exposure as the empty datagrams above. Datagrams from port 0 are now discarded, and a send error that concerns only the destination loses that datagram. A second ICMP error on the retry also loses the datagram instead of ending the session, and on Windows `WSAENETRESET` is handled like the other ICMP errors. See [#637](https://github.com/stepfunc/dnp3/pull/637).
* :shield: Keep a Windows UDP master or outstation running when it receives a datagram larger than its read buffer. Windows reports such a datagram as an error (`WSAEMSGSIZE`) instead of truncating it as Unix does, and the error ended the session, closing the socket until it reopened. Any host that can reach a bound UDP master or outstation could end its session with one oversized datagram and keep it down by repeating it; a connected (`OneToOne`) outstation only accepts datagrams from its peer's address. Every release with UDP support (1.6.0 and later) is affected on Windows; Unix, TCP, TLS and serial are not. The datagram is now discarded. See [#699](https://github.com/stepfunc/dnp3/pull/699).
* :bell: **The minimum supported Rust version is now 1.88.** See [#502](https://github.com/stepfunc/dnp3/pull/502).
* :bell: Deprecate `WriteError::IinError`, `TimeSyncError::IinError`, `TimeSyncError::SystemTimeNotUnix`, `CommandResponseError::Request` and `ObjectParseError::UnsupportedQualifierCode`, which are never returned. They will be removed in 2.0. See [#556](https://github.com/stepfunc/dnp3/pull/556).
* :star: Every public type in the Rust crate implements `Debug`. See [#519](https://github.com/stepfunc/dnp3/pull/519).
* :bell: Defining a visible string, octet string or bit string device attribute longer than 255 bytes now fails with the new `AttrDefError::BadValue` (`bad_value` in the bindings). Such attributes were accepted but could never be encoded, so READs left them out. See [#567](https://github.com/stepfunc/dnp3/pull/567).
* :star: Export `LinkError`, `FrameError` and `LogicError` from `dnp3::link`. `TaskError::Link` contained a `LinkError` that Rust users couldn't name. See [#539](https://github.com/stepfunc/dnp3/pull/539).
* :star: Bindings: add `unsupported_response` and `unsupported_or_bad_response` to every master task error enum (`task_error`, `read_error`, `command_error` and the others). A response the master can't parse now reports which kind of problem it is; it was always `bad_response`. Existing values keep their numbers, but code that switches exhaustively over these enums must handle the new values, and cases that were `bad_response` can now arrive as either new value. See [#653](https://github.com/stepfunc/dnp3/pull/653).
* :bug: Fix an outstation resending the first fragment's header and length when a READ is repeated while it waits for confirmation of a later fragment. It now resends the fragment awaiting confirmation. See [#504](https://github.com/stepfunc/dnp3/pull/504).
* :bug: Fix a file reader that aborts in `opened` being told the read failed with `Shutdown`, or with the CLOSE's error, instead of `AbortByUser`. See [#547](https://github.com/stepfunc/dnp3/pull/547).
* :bug: Fix the master's file read accepting a block for a file handle other than the one it opened, delivering it to the reader and completing the transfer. The read now ends with `WrongHandle` and closes the opened file. See [#631](https://github.com/stepfunc/dnp3/pull/631).
* :bug: Encode signed integer device attributes of 127 and 32,767 in one and two bytes, the smallest sizes that hold them, instead of the next size up. See [#517](https://github.com/stepfunc/dnp3/pull/517).
* :bug: Report file authentication tasks to the association handler as `FileAuth` instead of `GetFileInfo`. See [#548](https://github.com/stepfunc/dnp3/pull/548).
* :bug: Fix the master failing a floating-point analog output command (g41v3, g41v4) with a NaN value with `ObjectValueMismatch`, even when the outstation echoed it exactly. Echoed values are now compared by their exact bits, so an echo of -0.0 for 0.0 no longer matches. See [#613](https://github.com/stepfunc/dnp3/pull/613).
* :bug: Fix the master sending a different command than requested for a `ControlCode` whose `OpType::Unknown` or `TripCloseCode::Unknown` value encodes to a named code, and then failing the echo check after the outstation may have operated. Such codes are now rejected before anything is sent, in every command mode, with the new `BadEncoding::ControlCode`. The bindings can't build them. See [#636](https://github.com/stepfunc/dnp3/pull/636).
* :bug: Fix the outstation's event counts when a full event buffer discards an event that was written and awaiting confirmation. The class IIN bits could be wrong until the next confirm. See [#513](https://github.com/stepfunc/dnp3/pull/513).
* :bug: Fix the outstation losing events from an unsolicited response that was never confirmed, because the confirm timed out or DISABLE_UNSOLICITED ended the series. A READ before the next unsolicited retry left them out, and confirming that READ's response deleted them. See [#546](https://github.com/stepfunc/dnp3/pull/546).
* :bug: Fix an outstation READ including events of a class it didn't ask for. When an unsolicited response could hold none of the events it selected, those events stayed selected, and the next READ of another class reported them. See [#634](https://github.com/stepfunc/dnp3/pull/634).
* :bell: Outstations now report binary and double-bit input events recorded while the clock was unsynchronized with relative time (g2v3/g4v3 after a g51v2 CTO) when g2v2/g4v2 is the chosen variation, as TB2017-003a requires; g2v2/g4v2 carry only events recorded while synchronized. Events with no time are reported without time (g2v1/g4v1). See [#646](https://github.com/stepfunc/dnp3/pull/646).
* :bug: Fix an outstation configured for one master answering fragments it couldn't classify, such as an unknown function code, from other masters. In the solicited confirm wait this also ended the wait. Every fragment from another master is now dropped, without ending a confirm wait, clearing a control selection or refreshing the link-status keep-alive. See [#619](https://github.com/stepfunc/dnp3/pull/619).
* :bug: Fix a connected UDP session ending when its remote port isn't listening yet, as when an outstation starts before its master. On Linux and macOS the ICMP port unreachable reply surfaced as `ConnectionRefused` on the next read or write, which closed the session and dropped traffic until it reopened. See [#524](https://github.com/stepfunc/dnp3/pull/524).
* :bug: The master TCP server now checks the start bytes, length and CRC of the link header it reads to identify an outstation. A malformed header closes the connection instead of reaching `accept_link_id`. See [#586](https://github.com/stepfunc/dnp3/pull/586).
* :bug: Call `connect_failed` on every failed TCP or TLS connection attempt. It was only called when the attempt timed out, not when the connection was refused or the TLS handshake failed. See [#550](https://github.com/stepfunc/dnp3/pull/550).
* :bug: Fix an outstation server bound to an IPv6 wildcard address (`[::]`) rejecting IPv4 masters whose `AddressFilter` entry is written as IPv4. They arrive as IPv4-mapped IPv6 addresses, which no IPv4 entry matched. The native and mapped forms of an IPv4 address are now the same address, so two outstations whose filters differ only by that form now conflict. See [#644](https://github.com/stepfunc/dnp3/pull/644).
* :bug: Fix a bound UDP endpoint losing the sender's address for the second and later link frames in a datagram, which ended the session when it replied. See [#510](https://github.com/stepfunc/dnp3/pull/510).
* :bug: Fix the link layer losing a valid frame after corrupt input in discard mode when the corrupt bytes arrived in an earlier read than the frame, which byte-at-a-time serial reads always do. Affects serial, UDP in stream mode and TCP with `LinkErrorMode::Discard`. Incomplete frames are now parsed again from their first byte, and stream read buffers are 291 bytes larger so a UDP datagram is never truncated behind an incomplete frame. See [#658](https://github.com/stepfunc/dnp3/pull/658).
* :bug: Fix the master refreshing the keep-alive of the wrong outstation when several share a channel: a response refreshed the outstation the current task was for, not the one that sent it. See [#553](https://github.com/stepfunc/dnp3/pull/553).
* :bug: Fix requests queued for an association failing with `Shutdown` when the association is removed, while the master keeps running. They now fail with `NoSuchAssociation`, and a queued file read is aborted with that error. See [#632](https://github.com/stepfunc/dnp3/pull/632).
* :bug: Follow the transport reception rules of TB2013-003: a segment that repeats the previous one is discarded without losing the fragment being assembled, and a fragment with no data is no longer passed to the application layer. Affects masters and outstations. See [#508](https://github.com/stepfunc/dnp3/pull/508).
* :bug: Fix the master never timing out a link status request while API messages keep arriving: each message restarted the response timeout. See [#552](https://github.com/stepfunc/dnp3/pull/552).
* :bug: Log the cause when a master startup integrity scan, automatic event scan or single read fails; only periodic polls did. A `TaskError::MalformedResponse` now displays as unsupported, invalid, or unsupported-or-invalid response content according to its parse error, instead of always "malformed response". See [#647](https://github.com/stepfunc/dnp3/pull/647).
* :bug: Fix the master's link status check succeeding on any link-layer frame, such as a LINK_STATUS from another outstation on a shared channel or a REQUEST_LINK_STATUS sent by the outstation. It now succeeds only on a LINK_STATUS from the association's outstation, and times out otherwise. See [#614](https://github.com/stepfunc/dnp3/pull/614).
* :bug: Fix link-layer confirmed user data from one peer being acknowledged and then dropped as a repeat because another peer had reset the link or sent its own confirmed frames. The reset and frame count bit state now belongs to the source that reset the link, and confirmed data from any other source is ignored without an acknowledgement until that source resets. Affects masters with several outstations on a channel and outstations that receive link frames from more than one source. See [#635](https://github.com/stepfunc/dnp3/pull/635).
* :bug: Fix a link-layer acknowledgement or link status reply being lost or cut short when a read was interrupted by a timeout or an API call while the reply was being written. A lost acknowledgement made the retransmitted frame look like a repeat, so it was acknowledged and dropped. Replies are now always completed before the next read or write. See [#645](https://github.com/stepfunc/dnp3/pull/645).
* :bug: Fix a master task failing with `TaskError::Transport` when another outstation on the same channel sent a fragment the master couldn't parse, and a link status check failing on any response fragment from another outstation. Fragments from other outstations are now ignored (unsolicited responses are still processed) and the task keeps its original deadline. See [#620](https://github.com/stepfunc/dnp3/pull/620).
* :bell: Log expected traffic at debug instead of warn (frames and responses from other outstations, repeated segments, segments that arrive while a fragment waits), and log unsupported or ignored object headers once per fragment or request, with a count. See [#685](https://github.com/stepfunc/dnp3/pull/685).
* :bell: The master now confirms a response to a non-READ request (a control, restart, time sync, file or other task) when the outstation sets CON, before sending its next request, as IEEE 1815-2012 4.3 rule 13 requires. Responses whose objects can't be parsed are still not confirmed. See [#689](https://github.com/stepfunc/dnp3/pull/689).
* :book: Add a guide page explaining the master's automatic tasks (startup, restart handling, event scans, time sync, keep-alive) and how a channel schedules them alongside user requests and polls. See [#700](https://github.com/stepfunc/dnp3/pull/700).
* :bug: Fix an empty `AddressFilter::AnyOf` conflicting with `AddressFilter::Any` only when it was added second; an empty set now conflicts with no filter in either order. See [#697](https://github.com/stepfunc/dnp3/pull/697).
* :bell: Restart, time sync, file read, `write_dead_bands` and `send_and_expect_empty_response` tasks now fail with `MalformedResponse` and the parse cause when a response's objects can't be parsed, as commands and the other file tasks already do. In the bindings this can now be reported as an unsupported response instead of a bad one. `UnexpectedResponseHeaders` is still reported for well-formed responses with the wrong headers. See [#696](https://github.com/stepfunc/dnp3/pull/696) and [#702](https://github.com/stepfunc/dnp3/pull/702).
* :bell: When needed, the master's automatic time sync now runs before the integrity scan at startup and after a restart, as IEEE 1815-2012 5.1.1.2 orders, instead of after it. A failed time sync retries after the integrity scan and no longer blocks other tasks while waiting for its retry. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :star: Add `TaskError::SystemTimeNotAvailable` (`system_time_not_available` in the bindings' `task_error`). An automatic time sync that can't start because the `AssociationHandler` provides no system time now reports failure to `AssociationInformation`; it was not reported. Losing the system time during a sync now reports this error instead of `UnexpectedResponseHeaders`. Code that switches exhaustively over `task_error` must handle the new value. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :bug: Fix the master's automatic event scan waiting for a later response to report remaining events again. It now repeats at once when its response returns events and still reports events in the scanned classes, unless a fragment reports an IIN2 request error. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :bug: Fix the master skipping part of the post-restart sequence when the outstation reported a restart in the response to the integrity scan or ENABLE_UNSOLICITED. The sequence now starts over. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :bug: Fix a poll demanded while it was running having no effect. The poll now runs again once that run completes or fails. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :bug: Fix a clear restart answered with DEVICE_RESTART still set being reported to `AssociationInformation` as a success while the master retried it. It now reports `UnexpectedResponseHeaders`. See [#708](https://github.com/stepfunc/dnp3/pull/708).
* :bell: An outstation that receives DISABLE_UNSOLICITED while waiting for an unsolicited confirm now keeps waiting, as TB2015-002a requires: a confirm still clears the reported events, and if the wait times out the series ends without a retry and the events are reported later. Before, a direct DISABLE_UNSOLICITED ended the series at once, so a late confirm couldn't clear the events and they were reported again, and a broadcast one left the response retrying. See [#691](https://github.com/stepfunc/dnp3/pull/691).
* :bug: Fix the master reading 1-byte signed integer device attributes as unsigned, for example -1 as 255. See [#500](https://github.com/stepfunc/dnp3/pull/500).
* :bug: Treat device attributes defined in `AttrSet::Private(0)` as the default set (0). They skipped the default set's type checks and a master couldn't read them. See [#565](https://github.com/stepfunc/dnp3/pull/565).
* :bug: Report outstation static points whose flags aren't just ONLINE in a variation with flags, when a variation without flags is requested (counters, frozen counters, analog inputs). See [#484](https://github.com/stepfunc/dnp3/pull/484).
* :bug: Support analog input deadband (g34) READ of g34v0 and WRITE of g34v1 to g34v3 with start-stop qualifiers 0x00 and 0x01, required at Subset Level 4 by TB2016-003b. They were answered with IIN2.2. A master now ignores a g34v0 range header in a response instead of rejecting the response. See [#648](https://github.com/stepfunc/dnp3/pull/648).
* :bell: File and directory reads that the outstation ends with a content failure (an unsuccessful OPEN status, an authentication key of 0, an unexpected variation or block number) now report `task_fail` with `TaskError::UnexpectedResponseHeaders` to `AssociationInformation` instead of `task_success`, which affects task health counters. The `FileReader` callbacks are unchanged, and a reader abort or the maximum file size still doesn't fail the task. See [#621](https://github.com/stepfunc/dnp3/pull/621).
* :bell: A file or directory read that ends early on a content error, a reader abort or the maximum file size now sends one CLOSE so the outstation can release the file, and a CLOSE with a bad status, handle or variation now fails the task, including after a completed transfer (the reader's result is unchanged). No CLOSE is sent after a response timeout or transport error, short of the recommendation in IEEE 1815-2012 4.4.17.3 and 4.4.17.5. The cleanup can take up to one more response timeout. See [#626](https://github.com/stepfunc/dnp3/pull/626).
* :bell: While an outstation waits for an unsolicited confirm, a solicited confirm now clears a reported mandatory broadcast's IIN1.0 only if it matches the sequence of the response that asked for it and arrives before its confirm timeout. Any solicited confirm used to clear it. See [#625](https://github.com/stepfunc/dnp3/pull/625).
* :bell: Outstations now set IIN2.1 for a read of a point type with no points, and IIN2.2 for a range read that isn't fully installed, consistent with TB2016-001. Masters that explicitly poll types or ranges the outstation doesn't have will now see these errors. See [#487](https://github.com/stepfunc/dnp3/pull/487).
* :bell: Outside a READ, a count header for a variation that carries no data (g2v0, g4v0, g11v0, g22v0, g23v0, g32v0, g33v0, g42v0, g60v2-4 and g111v0) now makes the whole fragment malformed instead of being ignored. An outstation answers the request with IIN2.2 (parameter error) and processes none of its headers, and a master rejects the response as malformed and doesn't confirm it. READs of these variations are unchanged. See [#633](https://github.com/stepfunc/dnp3/pull/633).
* :bell: Adding an analog input or analog output status with a NaN or negative deadband now fails (`add` returns false) instead of adding a point that never, or always, reports value changes. A deadband written by a master (g34) now accepts positive infinity, which means value changes never produce events. See [#551](https://github.com/stepfunc/dnp3/pull/551).
* :bell: An analog input or analog output status of NaN reported in an integer variation (g30v1-v4, g32v1-v4, g40v1-v2, g42v1-v4) now sets OVER_RANGE; it was sent as 0 with no flag, like a real 0. Infinity in a single-precision variation (g30v5, g32v5/v7, g40v3, g42v5/v7) is now sent as infinity instead of the f32 maximum with OVER_RANGE. See [#649](https://github.com/stepfunc/dnp3/pull/649).
* :bell: Analog inputs and analog output status now create an event when the value changes between NaN and a number or infinity, under any deadband, including +infinity. Before, such a change created no event unless the flags also changed. NaN to NaN still creates none. See [#650](https://github.com/stepfunc/dnp3/pull/650).
* :bell: A negative analog input deadband written by a master (g34) is now accepted as 0, as IEEE 1815-2012 A.18 specifies, instead of being rejected with IIN2.2; `write_analog_dead_band` receives 0. A +infinity deadband now reads back as infinity in g34v3. A NaN deadband is still rejected. See [#651](https://github.com/stepfunc/dnp3/pull/651).
* :bell: Outstations now answer an analog output command (g41v3, g41v4) with a NaN or infinite value with NOT_SUPPORTED, before it reaches the `ControlHandler`, for SELECT, OPERATE, DIRECT_OPERATE and DIRECT_OPERATE_NR. See [#652](https://github.com/stepfunc/dnp3/pull/652).
* :bell: The master now processes a read response that has IIN2.0, IIN2.1 or IIN2.2 set instead of discarding it: the data reaches the `ReadHandler`, events are confirmed, and the rest of a multi-fragment response is read. A read that delivered data succeeds with a warning. One that delivered nothing still fails with `TaskError::RejectedByIin2`, except the startup integrity scan and automatic event scans, which complete so that they don't hold up polling. See [#536](https://github.com/stepfunc/dnp3/pull/536).
* :bell: The master now acts on the IIN1 bits (restart, need time, class events) of a non-read response that it rejects because of IIN2.0, IIN2.1 or IIN2.2, and still fails the task with `TaskError::RejectedByIin2`. See [#554](https://github.com/stepfunc/dnp3/pull/554).
* :bell: The master no longer confirms an unsolicited response whose objects can't be parsed. It used to confirm it, which let the outstation delete events the master never received; it now discards it with a warning, so the outstation keeps the events and retries. A response with relative-time events (g2v3, g4v3) and no preceding CTO in the same fragment is likewise discarded without a confirm, or fails a read with `TaskError::UnexpectedResponseHeaders`, as TB2018-001 requires, instead of delivering the events without a timestamp. See [#598](https://github.com/stepfunc/dnp3/pull/598).
* :bell: Outstations now set IIN2.1 instead of IIN2.0 for an object the function doesn't support, and IIN2.2 for a qualifier the object doesn't support, as TB2016-001 requires. This includes time writes and freezes the application declines with `RequestError::NotSupported`, and analog dead-band writes when they aren't supported. WRITE also accepts 2-byte qualifiers for time and IIN objects. See [#522](https://github.com/stepfunc/dnp3/pull/522).
* :bell: Parse count-qualified objects (qualifiers 0x07 and 0x08) according to the function code. An outstation now answers a READ of g50 with a count with IIN2.1 and keeps processing the headers after it, which were previously consumed as a timestamp. Count-qualified event objects outside a READ are now rejected as malformed (IIN2.2 from an outstation, `MalformedResponse` on the master) instead of being accepted without their data, which was then parsed as further headers. See [#593](https://github.com/stepfunc/dnp3/pull/593).
* :bell: Outstations now set IIN2.1 instead of IIN2.2 for a SELECT, OPERATE or DIRECT_OPERATE that contains an object other than a control, as TB2016-001 requires. See [#541](https://github.com/stepfunc/dnp3/pull/541).
* :bell: Outstations now discard a fragment that isn't a valid request under IEEE 1815-2012 clause 6 (FIR or FIN cleared, UNS set on anything but a confirm, or a response function code) and log a warning, instead of answering with IIN2.0. Unknown function codes still get IIN2.0. See [#525](https://github.com/stepfunc/dnp3/pull/525).
* :bell: The outstation now answers a repeated non-read request with its stored response octets unchanged in every state, as IEEE 1815-2012 Table 6-1 requires. From idle it used to OR in the current IIN. See [#560](https://github.com/stepfunc/dnp3/pull/560).
* :bug: Fix a READ that the outstation deferred while waiting for an unsolicited confirm setting IIN2.2 instead of IIN2.1 for an object that can't be read, and silently dropping headers past `max_read_request_headers` instead of setting IIN2.2. The setting's minimum of 64 now applies to deferred READs too. See [#529](https://github.com/stepfunc/dnp3/pull/529).
* :bug: Fix the outstation clearing IIN1.0 for a broadcast received during the unsolicited confirm wait before any response carried it, so the master never saw it. A stray solicited confirm could do the same for a mandatory-confirm broadcast. See [#573](https://github.com/stepfunc/dnp3/pull/573).
* :bug: Fix the outstation answering an OPERATE with NO_SELECT when the master confirmed an unsolicited response between the SELECT and the OPERATE ([#501](https://github.com/stepfunc/dnp3/issues/501)). The selection now follows IEEE 1815-2012 Table 4-9: confirms don't end it, a repeated DIRECT_OPERATE can no longer restore it, and a SELECT with the selection's sequence number but different objects is discarded. See [#530](https://github.com/stepfunc/dnp3/pull/530).
* :bell: A request whose objects can't be parsed now becomes the outstation's last request in every state, including the unsolicited confirm wait, so a following request that reuses an earlier sequence number is processed instead of echoed (IEEE 1815-2012 6.1). See [#561](https://github.com/stepfunc/dnp3/pull/561).

* :bug: Fix a malformed READ response when a device attribute doesn't fit in the rest of a fragment or can't be encoded. Its object header was left at the end of the fragment; the attribute now moves whole to the next fragment, or is skipped. See [#545](https://github.com/stepfunc/dnp3/pull/545).
