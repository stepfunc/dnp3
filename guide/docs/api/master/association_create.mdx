An association is how the master talks to one outstation on a channel. Add one to a `MasterChannel` with
`addAssociation` (`add_association` in Rust), and supply:

| What you supply | What it does |
|-----------------|--------------|
| Outstation address | Which outstation on the channel the association talks to |
| [AssociationConfig](./association_config.mdx) | The startup sequence, time synchronization, how the master reacts to the outstation, and timeouts |
| [ReadHandler](./read_handler.mdx) | Receives every value the outstation reports |
| [AssociationHandler](./association_handler.mdx) | Supplies the time for time synchronization |
| [AssociationInformation](./association_information.mdx) | Reports the start and outcome of each task |

Each outstation address can be used once per channel: the master rejects a second association with the same address.

On a UDP channel, use `addUdpAssociation` (`add_udp_association` in Rust), which also takes the outstation's endpoint;
see [UDP](./udp.mdx).

## Removing

An association stays on the channel until you remove it, even if you discard what `addAssociation` returned. Remove it
with `removeAssociation` on the `MasterChannel` (in Rust, `remove` on the association or `remove_association` on the
channel). This stops its polls and automatic tasks, and any of its requests still waiting in the queue fail.
