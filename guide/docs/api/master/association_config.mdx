`AssociationConfig` sets how the master works with one outstation. The outstation's address isn't part of it: you pass
the address separately when you [create the association](./association_create.mdx). The configuration answers these
questions:

| Decision | Why it matters |
|----------|----------------|
| What to read at [startup](#initialization) | The integrity poll gives you the current value of every point, at startup and after the outstation restarts |
| Whether the outstation reports unsolicited | Which event classes the master turns off and back on at startup. Choose none for an outstation that doesn't report unsolicited, and poll it instead |
| Whether and how to synchronize time | Whether the master sets the outstation's clock when it asks for the time, and with which procedure. See [Time Synchronization](./association_handler.mdx) |
| How to react to the outstation's indications | Which event classes the master scans when the outstation reports events, and whether it runs an integrity poll when the outstation's event buffer overflows |
| How long to wait, and how to retry | How long the master waits for each response, and how it [retries automatic tasks](./scheduling.mdx#when-something-fails) that fail |
| When to check a quiet link | How long the link can be silent before the master sends a keep-alive, if at all |
| How many requests can wait | How many of your requests can queue on the association before new ones fail at once |

## Initialization

The master turns unsolicited reporting off, reads everything with an integrity poll, then turns unsolicited reporting back
on. That way it starts from the current value of every point before changes stream in. If the outstation asks for the time
and automatic time synchronization is configured, the master synchronizes it before the integrity poll:

```mermaid
sequenceDiagram
    Master->>Outstation: Disable unsolicited reporting
    Outstation->>Master: Response
    opt outstation asks for the time and automatic time sync is configured
        Master->>Outstation: Time synchronization
        Outstation->>Master: Response
    end
    Master->>Outstation: Integrity poll
    Note over Master,Outstation: possibly several responses
    Master->>Outstation: Enable unsolicited reporting
    Outstation->>Master: Response
```

The master skips any step whose classes you leave empty. For an outstation that doesn't support unsolicited reporting, set
the classes to disable and to enable at startup to none, and the master performs only the integrity poll.

## Scheduling

The master runs these startup tasks, and others such as clearing the restart bit and automatic event scans, alongside your
requests and polls. See [Automatic Tasks and Scheduling](./scheduling.mdx) for when each one runs and how a channel orders
the work of its associations.
