`AssociationConfig` configures communication with a particular outstation:

* Timeout for responses on this association
* Startup handshaking
* If and how to perform time synchronization
* Per-association task queue size

The outstation address is provided as a separate argument when adding an association to a channel.

## Initialization

The DNP3 standard requires that the master perform these actions during initialization before normal polling can occur:

```mermaid
sequenceDiagram
    Master->>Outstation: Disable Unsolicited Reporting;
    Outstation->>Master: Response;
    opt outstation requests time and automatic time sync is enabled
        Master->>Outstation: Time synchronization;
        Outstation->>Master: Response;
    end
    Master->>Outstation: READ Class 1,2,3,0;
    Note over Master,Outstation: multiple responses/ACK possible here;
    Master->>Outstation: Enable Unsolicited Reporting;
    Outstation->>Master: Response;
```

If your outstation doesn't support unsolicited reporting, set `AssociationConfig.DisableUnsolClasses` and `AssociationConfig.EnableUnsolClasses` to `EventClasses.None()`. The master will skip unsolicited configuration and only perform the integrity poll.

## Scheduling

The master runs these startup tasks, and others such as clearing the restart bit and automatic event scans, alongside your
requests and polls. See [Automatic Tasks and Scheduling](./scheduling.mdx) for when each one runs and how a channel orders
the work of its associations.
